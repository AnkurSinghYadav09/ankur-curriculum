## Learning outcomes
By the end of this lecture, learners can:
- Explain why an API key must never be hard-coded in a script or notebook
- Configure a local repository with git init and the identity used for commit authorship
- Apply git add to stage only the files that belong in the next commit
- Write a commit message that states what changed and why
- Configure a .gitignore that excludes secrets, environments and generated files
- Configure a remote and push a local branch to GitHub for the first time

## Topics to cover
- Pre-recorded pre-work, watched after Session 1.1 which sets up the terminal and the virtual environment
- not a live lecture. Saving, versioning and sharing the course notebook
- git init and commit identity from the terminal
- staging with git add
- commits with clear messages
- environments & secrets: why API keys never go in code, and a .gitignore that keeps secrets and the virtual environment out of the repo
- pushing the course repo to GitHub
