## Topics covered
- Builds on 3.2: every 3.2 query read one table, but restaurant details sit in a second one, so the tables must be matched on a key
- INNER JOIN of orders with restaurants
- LEFT, RIGHT and FULL OUTER joins compared by which unmatched rows survive each
- choosing the join type a reporting question actually needs
- finding orders with no matching restaurant
- what happens to the row count when the join key repeats on one side, and the inflated totals that follow

## Learning objectives
By the end of this session, learners can:
- Join two tables on a matching key using INNER JOIN
- Compare INNER, LEFT, RIGHT and FULL OUTER joins by which unmatched rows survive
- Select the join type for a stated reporting requirement, justifying by which rows must survive
- Retrieve rows present in one table but absent from another using LEFT JOIN
- Predict the row count of a join when the key repeats on one side
